Example: hit, grab and takedown ​

Two NPC fighters are moving around the arena. One throws a punch. If the punch connects, it turns into a grab, and the grab flows into a takedown. Every player sees it on the same frame, and the damage happens on the server exactly when the slam lands.

This pattern fits any game where units fight each other: arena fighters, auto-battlers, tower defense heroes, boss fights.

How it fits together ​

  • Two scenes. Punch has one role and can miss. GrabTakedown has two roles and only plays when the punch connects.
  • The server decides. Markers fire on the server under PlayForAll, so the hit check and the damage run in server code instead of after a guessed task.wait.
  • No pop between scenes. The grab scene starts from the exact pose the punch has on its Hit frame.

1. Make the Punch scene ​

  1. Hub > Scenes > New scene, name it Punch.
  2. Select an NPC rig and Add actor from selection. Rename the role Attacker.
  3. Hub > Scene origin > Characters move from: Own root part. The punch then plays from wherever the unit stands, like a native Roblox animation.
  4. Animate the punch. A small lunge forward on the root is fine.
  5. On the frame the fist connects, right click the ruler > Add marker, name it Hit.
  6. With the playhead on Hit, pick the rig and copy its pose (Shift+C in the viewport).

2. Make the GrabTakedown scene ​

  1. New scene GrabTakedown. Add two rigs as actors and name the roles Attacker and Target.
  2. Characters move from: Scene origin. Both units move relative to one shared origin.
  3. Select the Attacker stand-in's HumanoidRootPart and Use selection as origin. The origin is now the attacker's root, which is what the game passes as the Anchor.
  4. Set Align: Attacker to Snap (it's already at the origin) and Target to Blend (it slides into the grab from wherever it stood).
  5. At frame 0, pick the Attacker and paste the pose (Shift+V). The grab then starts from the punch's Hit pose, so the switch between scenes doesn't show.
  6. Animate the grab and the takedown on both rigs. Use pins to keep the attacker's hand on the target's collar, and onion skin to check the spacing.
  7. Add markers: Slam on the impact frame, and optionally Grabbed near the start.

One scene or two?

If the takedown sometimes changes (a slam, a throw, a suplex), split it: Grab then Takedown_Slam, Takedown_Throw. Chain them on the grab's Ended or a marker near its end, the same way the punch chains into the grab below.

3. The server code ​

This module runs the whole sequence. It assumes your unit models have a Humanoid and a HumanoidRootPart, and that your game already has a way to hand a unit over to a scene and take it back. Here that's a UnitControl module with Take and Release. Swap in your own.

luau
-- ServerScriptService/Combat/GrabCombo.luau
local ReplicatedStorage = game:GetService "ReplicatedStorage"

local AcesMotion = require(ReplicatedStorage.AcesMotion)
local UnitControl = require(script.Parent.UnitControl) -- your game's own

local GRAB_RANGE = 6 -- studs, from the attacker's root to the target's
local SLAM_DAMAGE = 35

AcesMotion.Preload({ "Punch", "GrabTakedown" })

local GrabCombo = {}

local function isBusy(unit: Model): boolean
	return #AcesMotion.GetPlaying(unit) > 0
end

local function isAlive(unit: Model): boolean
	local humanoid = unit:FindFirstChildOfClass "Humanoid"
	return unit.Parent ~= nil and humanoid ~= nil and humanoid.Health > 0
end

-- The attacker's root, levelled: the scene's origin, so the grab plays on flat ground.
local function flatAnchor(unit: Model): CFrame
	local root = unit:GetPivot()
	local look = root.LookVector * Vector3.new(1, 0, 1)
	if look.Magnitude < 1e-3 then
		return CFrame.new(root.Position)
	end
	return CFrame.lookAt(root.Position, root.Position + look)
end

local function canGrab(attacker: Model, target: Model): boolean
	if not isAlive(attacker) or not isAlive(target) or isBusy(target) then
		return false
	end
	local offset = target:GetPivot().Position - attacker:GetPivot().Position
	local inFront = offset.Unit:Dot(attacker:GetPivot().LookVector) > 0.3
	return offset.Magnitude <= GRAB_RANGE and inFront
end

local function startGrab(attacker: Model, target: Model)
	UnitControl.Take(target)

	local grab = AcesMotion.PlayForAll("GrabTakedown", { Attacker = attacker, Target = target }, {
		Anchor = flatAnchor(attacker),
		FadeIn = 0.12, -- how long the Target's Blend slide takes
	})

	grab:GetMarkerSignal("Slam"):Connect(function()
		local humanoid = target:FindFirstChildOfClass "Humanoid"
		if humanoid then
			humanoid:TakeDamage(SLAM_DAMAGE)
		end
	end)

	-- If either unit is removed or dies mid-grab, end it cleanly.
	local function interrupt()
		if grab:IsPlaying() then
			grab:Stop(0.15)
		end
	end
	local destroyingAttacker = attacker.Destroying:Connect(interrupt)
	local destroyingTarget = target.Destroying:Connect(interrupt)

	grab.Ended:Once(function()
		destroyingAttacker:Disconnect()
		destroyingTarget:Disconnect()
		-- CommitRoot (on by default) already put both units where the takedown left them.
		UnitControl.Release(attacker)
		UnitControl.Release(target)
	end)
end

function GrabCombo.Punch(attacker: Model, target: Model)
	if isBusy(attacker) then
		return
	end
	UnitControl.Take(attacker)

	local punch = AcesMotion.PlayForAll("Punch", { Attacker = attacker })
	local grabbed = false

	punch:GetMarkerSignal("Hit"):Connect(function()
		if not canGrab(attacker, target) then
			return -- a miss: the punch plays out
		end
		grabbed = true
		-- Stop first: CommitRoot moves the attacker to where clients see it on the Hit frame,
		-- so the grab's Anchor matches the punch's last pose exactly.
		punch:Stop(0)
		startGrab(attacker, target)
	end)

	punch.Ended:Once(function()
		if not grabbed then
			UnitControl.Release(attacker)
		end
	end)
end

return GrabCombo

Call it when a unit attacks:

luau
GrabCombo.Punch(attacker, target)

4. The clients ​

Every client requires the runtime once. PlayForAll handles the rest, including players who join late.

luau
-- StarterPlayerScripts/AcesMotionClient (LocalScript)
require(game.ReplicatedStorage.AcesMotion)

Why it works ​

ConcernWhat handles it
Units drift during the animationFreezeActors: under PlayForAll the server anchors every unit the scene moves until it ends.
The target stands at a random spot when grabbedTarget Align Blend slides it into the authored grab position over FadeIn.
The scene plays in the wrong placeAnchor = flatAnchor(attacker) puts the scene's origin, the attacker's root, where the attacker really is.
A visible pop when the punch becomes a grabThe grab's frame 0 is the punch's Hit pose, and both switch on the same server frame.
Units snap back after the takedownCommitRoot (on by default for PlayForAll) moves them to where clients saw them land, then unanchors them.
Damage before or after the visual slamThe Slam marker fires on the server on the same frame clients show it.
One unit grabbed twiceisBusy checks AcesMotion.GetPlaying(unit) before starting.
A unit dies or is removed mid-grabinterrupt stops the grab with a short fade; Ended still releases both units.

Variations ​

Random takedowns. Split the scene and pick one when the grab ends:

luau
local TAKEDOWNS = { "Takedown_Slam", "Takedown_Throw", "Takedown_Suplex" }

grab.Ended:Once(function()
	if isAlive(attacker) and isAlive(target) then
		local name = TAKEDOWNS[math.random(#TAKEDOWNS)]
		AcesMotion.PlayForAll(name, { Attacker = attacker, Target = target }, {
			Anchor = flatAnchor(attacker),
		})
	end
end)

Hit-stop on the slam. Freeze both units briefly on impact, for every player:

luau
grab:GetMarkerSignal("Slam"):Connect(function()
	grab:SetSpeed(0)
	task.wait(0.08)
	grab:SetSpeed(1)
end)

Different unit skins. Units that share a skeleton play the same scenes as they are, since roles bind to whatever model you pass. For spawned effects that change per skin, use the Templates option.

Many fights at once. Each PlayForAll sends one message per play, not one per frame. In large arenas, let clients skip fights that are far away:

luau
-- LocalScript
AcesMotion.Configure({ MaxDistance = 250 })

Testing it in Studio ​

  1. Scrub both scenes in the editor with two test rigs to check the poses line up at the switch.
  2. In a play test, spawn two units close together and call GrabCombo.Punch(a, b) from the server command bar.
  3. Watch the output: a role with no instance warns once (check the role names), and a scene that can't be found errors with its name.
