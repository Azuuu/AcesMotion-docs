Networking ​

AcesMotion has networking built in. You choose where a scene plays; the runtime keeps every machine on the same frame.

The model ​

  • The runtime uses one RemoteEvent, AcesMotionRemote, under the runtime module. The server sends plays and changes to clients. The only thing a client sends is its own play on a model it owns (below); anything else goes through your own validated remotes.
  • Clients evaluate scenes themselves. A joint's Transform never replicates, so the server sends one message per play and per change (not per frame), and each client writes the pose.
  • Timing follows the server clock. Every message carries where the server's clock was. A client plays from there, and if it's more than 0.05 s off it jumps to the right time without firing events.

Choosing a call ​

You wantCallFrom
Something only this player sees (a menu scene, a preview on a local model)Playclient
An emote or move on the player's own character, seen by everyone (like the Animator)Playclient
A shared moment every player sees, with server-side timing (cutscenes, abilities, finishers)PlayForAllserver
A server-driven pose where the server owns roots and propertiesPlayserver

PlayForAll ​

luau
-- Script (server)
local track = AcesMotion.PlayForAll("Finisher", { Attacker = attacker, Target = target }, {
	Camera = true,
})
track:GetMarkerSignal("Hit"):Connect(function()
	target.Humanoid.Health = 0 -- fires on the server at the same moment clients see the hit
end)
  • Every client plays the whole scene (Full); the server plays a timing copy that writes nothing.
  • Markers and Event blocks fire on the server and on clients.
  • Camera is off by default; pass Camera = true to give clients the cinematic camera.
  • Audience limits it to some players.

Server Play ​

luau
local track = AcesMotion.Play("Lever", { Lever = lever })

The server writes roots and properties (they replicate the usual way) and sends a joints-only copy to every client. It never takes a camera.

Every control call is mirrored ​

When the server calls Stop, Pause, Resume, SetTime, StepTime, SetSpeed, SetWeight, SetLayerWeight, SetLooped, SetTimeMap, SetCamera, SetCast or SetOptions on a shared track, every client playing it follows, on the same clock.

luau
-- Slow motion for everyone at the killing blow
track:GetMarkerSignal("Kill"):Connect(function()
	track:SetSpeed(0.25)
	task.wait(1)
	track:SetSpeed(1)
end)

Audience, FreezeActors and CommitRoot stay on the server.

Client plays on owned models ​

Like the Animator's tracks, a client's Play on a model it owns replicates: its own character, or anything whose physics it owns (an unanchored root part this client is the network owner of). Every other client plays it, late joiners included, and the control calls (Stop, SetTime, StepTime, SetSpeed, Pause, Resume, SetWeight, SetLayerWeight, SetLooped, SetTimeMap) follow it. Late joiners get its latest time map. Recasting, options and the camera stay on the owner's screen.

The server checks every request before relaying it:

  • every cast member's root part is owned by that player (GetNetworkOwner);
  • the scene is one the server can find by name (ReplicatedStorage.AcesMotionScenes or a folder given to RegisterFolder on the server): a client sends only the name, never scene data;
  • at most about 10 calls a second per player;
  • server-only options are dropped, and the copies never take anyone's camera.

When ownership moves to another player or to the server, or the player leaves, the play stops for everyone. A play whose cast the client doesn't own stays on that client (Studio prints a note once per scene). The server must require the runtime and register the folders your scenes live in. Turn it off with AcesMotion.Configure({ ClientReplication = false }) on the server and the clients.

Late joiners ​

A player who joins mid-play receives every live shared track (without an Audience) and starts at the current time; a looped one wraps. Past instant events don't fire for them.

StreamingEnabled ​

The server tags cast members AcesMotionCast with an AcesMotion_CastId attribute. A client that hasn't streamed an actor in yet binds it when it appears; nothing errors meanwhile.

Physics and ownership ​

While a PlayForAll plays, the server:

  • freezes moved actors (FreezeActors, default on), anchoring their root parts so physics and network ownership don't fight what clients see. A moved actor is one whose root the scene keys, attaches (a prop carried and dropped) or runs a Motion Warp, generator or constraint on. Player characters are never frozen.
  • commits them at the end (CommitRoot, default on), moving each one to where the clients left it, its attach keys and Motion Warp included, then unanchoring it. To match the clients, the server works out those roots each frame while the scene plays, so an Aim at launch warp lands where it aimed on the clients.
luau
track.Started:Connect(function()
	npcBrain:Pause()
end)
track.Ended:Connect(function()
	npcBrain:Resume()
end)

Requiring on each side ​

luau
-- StarterPlayerScripts (LocalScript): every client, once
require(game.ReplicatedStorage.AcesMotion)
luau
-- ServerScriptService (Script): only if the server plays scenes
local AcesMotion = require(game.ReplicatedStorage.AcesMotion)

A game whose clients only play scenes for themselves (UI cards, local effects) never needs it on the server. A client's Play on its own character reaches the other players only through the server, so require it there too.
