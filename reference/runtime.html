Runtime API ​

Every runtime note from the feature list, in one page. For signatures, parameters and examples, see the Runtime API.

Install and layout ​

  • Settings > About > Install runtime (or Update runtime, also on the Timeline's "Update runtime" banner) writes the module ReplicatedStorage.AcesMotion from the plugin itself: a ModuleScript (its source is a short note, the MIT licence, and a require) holding Engine, Runtime and Packages (Signal, Trove), with an AcesMotion_Version attribute. Updating keeps the root and replaces its children; scenes are untouched; one undo step. A place whose runtime is synced from files refuses the button. About shows "Not installed", "0.2.0 (up to date)", "(older, update it)" or "(newer than this plugin)".
  • local AcesMotion = require(game.ReplicatedStorage.AcesMotion). Every client requires it once to receive PlayForAll (a LocalScript in StarterPlayerScripts is enough). Requiring it on the server is optional: only PlayForAll and a server Play need it there (a client-only game never touches the server).
  • Scenes are found by name in ReplicatedStorage.AcesMotionScenes, then in every folder given to RegisterFolder (subfolders too, shallowest first, never inside a scene). A client can only play scenes it can see (not ServerStorage). Register the folder on every side that plays by name.
  • Custom generators: ModuleScripts tagged AcesMotionGenerator (anywhere both sides can require) register by module name and keep working after a rename; a generator the game can't find adds nothing (warned once).
  • Custom constraints: ModuleScripts tagged AcesMotionConstraint (anywhere both sides can require) register by module name and keep working after a rename; a constraint the game can't find does nothing, and one that doesn't load warns once.
  • Custom actions: ModuleScripts tagged AcesMotionAction (anywhere) register by module name; a module may return just a function (an instant action); RegisterAction also works for action blocks with that Action (run only where the scene plays in full). Modifiers: ReplicatedStorage.AcesMotionModifiers (stored; not evaluated yet).
  • AcesMotion.Version is the release version; AcesMotion.FormatVersion is the newest scene format it reads. A scene saved in a newer format is refused by name.

Functions ​

  • AcesMotion.Load(scene, cast?, options?) returns a Track in state Loaded: nothing bound, no camera taken, no movement lock. Errors at once if the scene is missing or newer than the runtime.
  • AcesMotion.Play(scene, cast?, options?) is Load then Track:Play(). On a client it plays locally. On the server it writes roots and properties there (Roblox replicates those) and sends the joints to every client, because a joint's Transform never replicates.
  • AcesMotion.PlayForAll(scene, cast?, options?) (server only): every client (or options.Audience) plays the whole scene; the server keeps only the clock, so markers and Event blocks fire in server code.
  • AcesMotion.Preload({ scene, ... }) decodes scenes ahead of time. AcesMotion.RegisterFolder(folder) adds a scene search folder.
  • AcesMotion.GetPlaying(actor?) lists playing tracks (or those playing actor); AcesMotion.StopAll(actor?).
  • AcesMotion.OnEvent(eventName, callback) calls callback(track, payload) whenever an Event block or a marker named eventName fires in any scene on this side; it returns a function that disconnects it.
  • AcesMotion.RegisterAction(name, module) and AcesMotion.RegisterModifier(name, module).
  • AcesMotion.RegisterGenerator(name, module): a custom generator kept somewhere untagged (the same table a tagged module returns; errors at once when it has no Offset).
  • AcesMotion.RegisterConstraint(name, module): a custom constraint kept somewhere untagged (the same table a tagged module returns; errors at once when it has no Solve).
  • AcesMotion.RegisterDriver(name, module): a custom driver kept somewhere untagged (the same table a module tagged AcesMotionDriver returns; errors at once when it has no Drive).
  • AcesMotion.Evaluate(scene, seconds, cast?) returns every actor's pose by role (track path to value), pure, nothing written.
  • AcesMotion.Configure { MaxDistance = number, ClientReplication = boolean }: clients skip scenes whose anchor is farther than this (off by default; 0 or less turns it off; a scene driving the camera, Manual included, or playing in a ViewportFrame is never skipped); ClientReplication (on by default) lets a client's Play on a model it owns replicate.
  • Client plays replicate like the Animator's: a client's Play on its own character (or anything whose physics it owns) plays on every other client and for late joiners, control calls included. The server checks ownership, finds the scene by name only, limits each player to about 10 calls a second, and stops the play for everyone when ownership moves or the player leaves. Plays on models the client doesn't own stay local.
  • Level of detail only for crowds: with up to 64 actors on screen (50 on phones; Configure { LodFullCount }) every visible actor poses every frame; past it the distance tiers start, coarser the bigger the crowd, and switch back below 80% of the count.
  • Level of detail (Configure { Lod, LodTiers, LodFullCount, CullOffscreen, FrameBudget }, PlayOption Important; LodTiers sets your own distances and rates, CullOffscreen = false keeps offscreen actors posing): on clients, offscreen actors don't pose and far ones pose less often (every frame within 80 studs, then 30, 20 and 12 times a second to 160, 320 and beyond; on phones within 60 studs, then 30, 20 and 10 to 120, 250 and beyond; a zoomed-in camera counts as closer), each on its own beat, holding the pose in between; clocks, markers and events always run every frame. A frame budget (1.5 ms on phones, 4 ms elsewhere) stretches the far distances while the runtime is over it; actors within the first tier always pose every frame. Crowds playing the same scene share one evaluation per moment. Scenes with nothing to do skip whole frames. Your own character, cameras and Important plays always pose every frame. An attached object poses on the frames what it's attached to poses, so the two never come apart (a far NPC's sword updates with its hand), and between them it's carried along when the game moves that actor; one stuck to something posing every frame (a player, a camera) does too. Spawned actors and actors whose stack is only Motion Warps take Lod like the cast (a projectile far off poses less often); another constraint or a driver keeps an actor at full rate.
  • Rigs in a ViewportFrame (an inventory card, a reveal, a shop preview) play like any cast: put the rig in the frame's WorldModel before Play. Level of detail judges the card by how it shows instead of by the world camera: it rests while it or anything above it is hidden, its ScreenGui is disabled, it's scrolled out of a list that clips it or it's off the screen, and picks up when shown again; on screen it counts as a rig as far away as one that size would look, so a crowd of icon-sized cards poses less often while a big card keeps every frame. MaxDistance leaves it alone, copies the scene spawns go into the card's WorldModel, and a client's Play on it never replicates.
  • Fast playback: each channel is prepared once per scene (no searching for keys every frame), joints are written without reading them back, events are found by time instead of scanning the scene, and the parts a frame moves go in one bulk move, so hundreds of characters or a thousand props can play at once.
  • Cast: { [Role] = Instance | { Instance } } (typed Instance | { any }, so a { Model } list passes the type checker; items that aren't instances are skipped). An empty role plays on its fallback (usually the stand-in). A list plays on its first item, except for an actor that repeats Per target over it (one copy per item, see Repeated actors below). A missing role with no fallback is skipped (warned once in Studio).

Track (what Load and Play return) ​

  • Methods: Play(), PlayForAll() (server), Stop(fadeOut?), Pause(), Resume(), SetTime(seconds) (jumps while playing and plays on; skips instants in between), StepTime(deltaSeconds) (negative goes backwards, fires everything crossed), SetSpeed, SetWeight, SetLayerWeight(name, weight), SetLooped(bool), SetCamera(bool | "Manual") / HasCamera(), GetCamera() (the scene's camera after this frame: CFrame, FieldOfView, Shot, Attached, plus the screen effects in Screen and the depth of field in Lens), AttachCamera(blendSeconds?) / DetachCamera(blendSeconds?) (hand the player's camera to the scene or back mid-play; detached, the scene's camera is still worked out for GetCamera), SetCast(cast), SetOptions(options), GetTime(), IsPlaying() (true while paused), Binds(instance) (whether it plays that instance as an actor), GetMarkerSignal(markerName), Destroy(). Track.Length is the play's length in seconds (LengthChanged fires when a Motion Warp timed by speed changes it).
  • Signals: Started (the first frame after Play, so connecting right after Play works), Stopped (Stop, or the end of a play that does not loop), Ended (fully done: fade-out over, joints released, roots committed), Looped, MarkerReached(markerName, payload), LengthChanged(length), CameraAttached, CameraDetached, ShotChanged(role?). Signals stay connected across plays.
  • A track can be replayed: Play after it ends plays it again; Play while it plays restarts it (an Ended handler that plays it again wins). Setters work before and during a play and last across plays; they never change the options table you passed.
  • Mid-play: SetCast lets go of the old instance (joints back to the Animator, movement lock undone) and binds the new one aligned from now; SetOptions re-clamps Range, rebinds on Anchor/Align, applies LockMovement, Manual, FadeIn/FadeOut, FreezeActors/CommitRoot live (StartTime and Audience apply from the next Play).
  • Stop(fadeOut) freezes the time and fades the pose out. At the end joints go back to what the Animator gives them; roots and properties keep the last value written. The weight and fades apply to joints and properties, never to the root.
  • Play time follows the shared server clock (workspace:GetServerTimeNow()), never the frame delta, so a hitch on one machine does not leave it behind.

PlayOptions ​

  • Anchor (CFrame, BasePart or Attachment): where the scene origin goes. Default: the scene's linked origin object, else its fixed origin. A part or attachment is followed every frame: the scene rides it as if welded (a moving platform, a vehicle, another character), position and rotation, under PlayForAll too (clients follow it where they see it); a far actor that Lod holds rides along without being posed again. FollowAnchor = false reads it once at the start instead. An anchor inside an actor this scene moves by its root isn't followed (the actor would chase its own anchor); a destroyed anchor leaves the scene where it last was.
  • CameraBlendIn, CameraBlendOut (seconds; default the scene's Camera in game settings, else 0 = cut): the view glides from the player's camera into the scene's first shot, and back to the player's camera when the scene lets it go (the player's camera script keeps working underneath, so it lands exactly where that camera is).
  • CameraBlendInEase, CameraBlendOutEase ("Smooth", "Linear", "EaseIn", "EaseOut") and CameraStopBlend (seconds back to the player's camera when stopped early; 0 snaps). Camera = "Manual": the scene's camera is worked out every frame but the player's is left alone, for the game to read with GetCamera() and apply itself. Signals CameraAttached, CameraDetached, ShotChanged(role?).
  • Screen (default true): the scene's screen effects (bars, vignette, blur, fade, colour, bloom, each camera's depth of field) draw while the scene drives the player's camera; false plays the camera without them. With Camera = "Manual" nothing is drawn: GetCamera() reports them.
  • Templates: { [role] = Instance }, a template per spawned role used instead of the scene's own, so one scene plays with many looks (templates that share a skeleton). Under PlayForAll the templates must be somewhere clients see (ReplicatedStorage).
  • Speed (1), Looped (false), Weight (1; below 1 blends over the Animator's pose), FadeIn, FadeOut (seconds), StartTime (seconds), Range ("All", "LoopRegion", or { from, to } in seconds), Layers (scales each named layer's authored weight), LockMovement (default true for the local player's character), Camera (default true for a local Play; a PlayForAll copy takes the camera only when the server track sets Camera = true, and a server Play never does), Manual (the runtime never advances it; only StepTime/SetTime do), Audience (PlayForAll only: a list of players; nil = everyone), Align (per-role override of Snap / Blend / None), FreezeActors (the server anchors moved actors' roots while playing; default true for PlayForAll), CommitRoot (the server sets final root CFrames at the end; default true for server-owned models).

What plays ​

  • Joints (Motor6D, AnimationConstraint, Bone) blended over whatever the Animator wrote that frame, by weight; released back on stop.
  • Root motion relative to the scene origin, each actor's root part, or per actor (Hub > Scene origin > Relative to). Align at the start: Snap (teleport to the authored spot), Blend (slide over FadeIn, 0.25 s by default), None (play where it stands); an older scene's Warp plays as Blend (a Motion Warp bends motion onto a target). Align only applies to actors with a root track.
  • Generators play live in games, worked out from the time like keys (so SetTime lands right): the same seed plays the same every time, unless a block is set to Vary each play.
  • Audio lanes: the scene's clips play wherever the scene plays (Play on one client, PlayForAll for everyone), each at its volume times its lane's, flat from SoundService or from its 3D part, starting partway on SetTime, a late start or a late join. A clip's Sound template must be somewhere the playing side can see (ReplicatedStorage or Workspace for clients). Roblox animations can't hold sound: Export lists "Audio: N clips" under what needs the runtime.
  • Attachments (Attach, Detach and Back to rig keys): an attached root, joint or bone follows its target from its Attach key, keeping where it was then, with its own keys on top; stays put from a Detach key; rejoins its rig from a Back to rig key (snapped back into place, eased over its blend, or where it is). Each Attach key carries the grip saved when it was made (an older key without one keeps the grip it has when the play reaches it). In a game, a Detach key drops the object where it is at that moment, not at the spot saved in Studio, so it lands right when the target or the anchor is somewhere else. A target the scene doesn't move (a dummy, an NPC, a player) is read where it stands now, so an object stuck to a walking target walks with it. A Model actor that moves by a part (Moves by) is placed by its part of the same name in whatever model plays the role, so swapped designs line up. Worked out from the time, so SetTime and StepTime land where a straight play would. A target that is not in the cast holds it where it was. A target whose root a generator moves (a Shake on its root, with or without root keys) carries what rides it the same way in a game as in Studio.
  • Held props ride a joint: while an Attach key holds a part or model actor on a part (a hand) or an Attachment in one, and the prop is unanchored or its Unanchor switch is on, the runtime joins it to the holder with a Motor6D named AcesMotionHold inside the prop, so a held prop costs nothing per frame (keys on the prop itself still apply on top). A model's parts that aren't joined to its main part (its Moves by part, else its PrimaryPart) are welded to it for the hold (AcesMotionHoldWeld). The joint goes when the hold ends (a Detach key, another target, SetTime outside the hold, Stop), and Anchored, Massless and CanCollide go back to how they were, so the prop stays where it was. Each client makes its own joint (nothing replicates); the server never does. An anchored prop with Unanchor off, a held rig, a rig's own joint, a Bone target and a prop with constraints or drivers keep the per-frame math.
  • Constraints (Track To, Copy, Limit, Floor...) run live after keys and attachments, each row's stack in order with its generators, so a constrained camera aims at whoever plays the target role. A constraint whose target isn't in the cast does nothing. A distance fade weighs each constraint by how far it is from what it measures to, every frame.
  • Drivers (Copy, Distance, Axis, Speed, Property, custom) run live in the same stacks as generators and constraints, on roots, joints, properties or one channel of them. A source the scene animates is read from the scene at that moment, so SetTime and late joins land right; one the scene doesn't animate (a game-set attribute, a player, a physics object) is read live every frame, and its Speed and Smooth follow it between frames. A driver whose source is missing does nothing (the keys play); one that reads what it drives is ignored. A whole Color3 driven by a number picks its colour from the block's colour ramp.
  • Roles the game fills in (an actor's Filled by): when the game's cast leaves the role out, the runtime fills it with the local player's character, the nearest player's character (nearest to the scene origin), the player's camera, or the nearest (or first) object with a tag, and picks again 10 times a second as players respawn and move. A role the game casts itself always wins. The server has no local player or camera, so those roles stay empty there.
  • Properties of any instance: numbers, vectors, UDim/UDim2, Color3, NumberRange, NumberSequence and ColorSequence (blended point by point), CFrame, and values that hold (Bool, Enum, Text, Asset); attributes; a Model's Scale.
  • Calls: a sound's Play() / Stop() (clones of the Sound with its effects and SoundGroup, or an AudioPlayer with its wires, playing the key's region, loop, speed and fades; at most 16 copies per sound, the oldest stopped first), an emitter's Emit() (with the burst's own particle life) and Clear(), a Trail's Clear(), a VideoFrame's Play() / Pause(). Calls run in Full mode, not in the server's timing copy.
  • Camera actors take the camera (CFrame and FOV) on a client's full play unless Camera is false; SetCamera(false) gives it back mid-play. A switch key's Blend glides into its shot from the camera before it (eased in and out, the outgoing camera still moving as keyed); the first shot, or one after a gap, glides from the player's view. Several camera actors: only the live one drives the camera, chosen by the scene's Camera track switch keys (the last switch at or before the time; before the first switch, its camera; with no switches, the first camera actor in the cast; a muted camera or track is skipped). Scrubbing, SetTime and playing all agree.
  • Spawned actors are cloned from their template (found by its AcesMotionTemplate tag and id wherever it is, else by its saved path like ReplicatedStorage/AcesMotionTemplates/SlashArc) into workspace.AcesMotionSpawned at their spawn frame, anchored, at their socket or the origin; they are destroyed at their Until, or Lifetime seconds after the scene ends, or when it ends; with Linger on, a spawned actor that disappears mid-scene stays its Lifetime more so its trails and particles finish; a Parent to actor goes inside that part, welded; scrubbing back before the spawn frame removes the clone. A looped play keeps its clones between passes (out of the world, put back on the next pass) instead of cloning again. Under PlayForAll the clones are client-side (visual only).
  • Markers fire MarkerReached and GetMarkerSignal. Event blocks (params Name, Payload) fire those and OnEvent; other action blocks run the module registered under their Action name, only in Full mode. (Blocks are added on the Timeline's action tracks; their parameters are edited in the Inspector from the next update.)
  • Motion Warps re-fit each trip to where things really are (a target the scene doesn't move is read where it stands now; Aim at launch keeps where it was when the trip began, each play and each loop); after the trip it keeps its landing until the next warp on the row, or until an Attach or Detach key on that row takes the actor over (a sticky shot that drops later); one timed By speed is worked out when the play reaches it (from where its start and target are then), and the play's Length follows (LengthChanged fires). Marker holds freeze the scene (or one actor) and a Camera kick shakes the local camera over a scene marker's hold.
  • Repeated actors: a Per target actor plays one copy per item of its Over role's list (Cast = { Targets = { a, b, c } }; the other items play as "Targets#2", "Targets#3"... in the cast, which networked copies use, and each copy lands on its own item), an empty list none; a Count actor plays its copies with their Spread. Each copy has its own warp, timing and Stagger, and its actor markers carry Target. The play lasts until the last copy ends.
  • Joint warps (Bends Joints, Path and joints) solve the chain live with the same IK as Studio, so a claw closes on wherever the target really is.
  • Layers play in games as in Studio: each actor's keys on a layer blend over Base by the layer's mode, weight curve, mask, mute and solo. options.Layers = { Polish = 0.5 } and Track:SetLayerWeight(name, weight) scale a layer's authored weight by its name from the next frame (under PlayForAll too). Not at runtime yet: modifiers.

Networking ​

  • One RemoteEvent, AcesMotionRemote, under the runtime module, server to clients; the only thing a client sends is its own play on a model it owns, which the server checks and relays. Messages carry the server clock, so a client re-anchors rather than drifts (it jumps without firing events when more than 0.05 s off).
  • Late joiners receive the live tracks and start at the current time (a looped one wrapped). Streamed-in actors (StreamingEnabled): cast members are tagged AcesMotionCast with an AcesMotion_CastId attribute, and a client binds a member that was not streamed in when it appears.
  • The server sends the anchor it resolved and each moved actor's start root so every client aligns alike. A server Play shares itself as a joints-only copy (plus the owning client's own character root).
  • FreezeActors anchors moved actors on the server while a PlayForAll plays and CommitRoot pivots them to where the clients left them (attach keys, Motion Warps, root generators and constraints included: the server solves those roots each frame meanwhile, so launches and drop spots match), then unanchors; an actor counts as moved when the scene keys, attaches or stacks its root; player characters are never frozen. Track.Started / Ended let games pause and resume NPC logic.
  • The server never needs to require the runtime for a client-only game.
