Runtime API ​

Every runtime note from the feature list, in one page. For signatures, parameters and examples, see the Runtime API.

Install and layout ​

The runtime is one ModuleScript, ReplicatedStorage.AcesMotion, written into your place by the plugin itself.

Install or update ​

  • Settings > About > Install runtime writes the module. Update runtime sits in the same place and on the Timeline's "Update runtime" banner.
  • The module is a ModuleScript holding Engine, Runtime and Packages (Signal, Trove), with an AcesMotion_Version attribute. Its source is a short note, the MIT licence, and a require.
  • Updating keeps the root and replaces its children. Scenes are untouched, and the whole update is one undo step.
  • A place whose runtime is synced from files refuses the button.
  • About shows "Not installed", "0.2.0 (up to date)", "(older, update it)" or "(newer than this plugin)".

Require it ​

lua
local AcesMotion = require(game.ReplicatedStorage.AcesMotion)
  • Every client requires it once to receive PlayForAll. A LocalScript in StarterPlayerScripts is enough.
  • Requiring it on the server is optional. Only PlayForAll and a server Play need it there, so a client-only game never touches the server.

Where scenes are found ​

  • By name, in ReplicatedStorage.AcesMotionScenes, then in every folder given to RegisterFolder. Subfolders count too, shallowest first, never inside a scene.
  • A reference finds its scene by id instead: in those folders and in every folder tagged AcesMotionScene, wherever it is, including scenes that stream in later.
  • If two scenes share an id (one was copied in the Explorer), the runtime warns once and plays the first it finds.
  • A client can only play scenes it can see (not ServerStorage). Register the folder on every side that plays by name.

  • RegisterAction also works for action blocks with that Action. They run only where the scene plays in full.
  • Modifiers live in ReplicatedStorage.AcesMotionModifiers (stored; not evaluated yet).

Versions ​

  • AcesMotion.Version is the release version.
  • AcesMotion.FormatVersion is the newest scene format it reads. A scene saved in a newer format is refused by name.

References ​

A reference is a Configuration tagged AcesMotionClip.

CallWhat it does
AcesMotion.Play(model, "Punch")Plays the reference named Punch, found anywhere inside model.
AcesMotion.Play(reference, model)The same, when you already have the reference.
AcesMotion.Play(reference, { Attacker = npc, Target = enemy })Casts the roles yourself.

Load and PlayForAll take the same arguments, and Preload and Evaluate accept a reference.

Each role goes to the first of these that has someone:

  1. The cast table in code.
  2. The reference's cast entries.
  3. The model, if the reference's AcesMotion_Role names this role.
  4. The model, if this is the only role still empty.
  5. The actor's game target or fallback.
  • A cast entry whose target is gone or streamed out is skipped.
  • If two or more roles are still empty and no role is set, the call errors and lists them.

Where it plays: the Anchor option, else the reference's anchor, else the scene's anchor, else the scene's authored origin.

Configure ​

AcesMotion.Configure { ... } sets options for the whole runtime.

OptionDefaultWhat it does
MaxDistanceOffClients skip scenes whose anchor is farther than this number. 0 or less turns it off.
ClientReplicationOnLets a client's Play on a model it owns replicate.
Lod, LodTiers, LodFullCount, CullOffscreen, FrameBudgetLevel of detail, below.

MaxDistance never skips a scene driving the camera (Manual included) or playing in a ViewportFrame.

Cast ​

  • A cast is { [Role] = Instance | { Instance } }.
  • It's typed Instance | { any }, so a { Model } list passes the type checker. Items that aren't instances are skipped.
  • An empty role plays on its fallback (usually the stand-in).
  • A list plays on its first item, except for an actor that repeats Per target over it (one copy per item, see Repeated actors below).
  • A missing role with no fallback is skipped (warned once in Studio).

Client plays replicate like the Animator's ​

  • A client's Play on its own character (or anything whose physics it owns) plays on every other client and for late joiners, control calls included.
  • The server checks ownership and finds the scene by its id (else its name) among the ones it can see.
  • It limits each player to about 10 calls a second.
  • It stops the play for everyone when ownership moves or the player leaves.
  • Plays on models the client doesn't own stay local.

Level of detail ​

Level of detail is only for crowds. With up to 64 actors on screen (50 on phones; Configure { LodFullCount }), every visible actor poses every frame. Past that count the distance tiers start, coarser the bigger the crowd, and they switch back below 80% of the count.

  • Settings: Configure { Lod, LodTiers, LodFullCount, CullOffscreen, FrameBudget } and the PlayOption Important.
  • LodTiers sets your own distances and rates. CullOffscreen = false keeps offscreen actors posing.
  • On clients, offscreen actors don't pose and far ones pose less often:
ElsewhereOn phones
Every frame within 80 studsEvery frame within 60 studs
30 times a second to 160 studs30 times a second to 120 studs
20 times a second to 320 studs20 times a second to 250 studs
12 times a second beyond10 times a second beyond
  • A zoomed-in camera counts as closer.
  • Each actor poses on its own beat and holds the pose in between. Clocks, markers and events always run every frame.
  • A new play checks on its first frame whether each actor is on screen, so a move replayed over and over off screen never poses.
  • A frame budget (1.5 ms on phones, 4 ms elsewhere) stretches the far distances while the runtime is over it. Actors within the first tier always pose every frame.
  • Crowds playing the same scene share one evaluation per moment. Scenes with nothing to do skip whole frames.
  • Your own character, cameras and Important plays always pose every frame.
  • An attached object poses on the frames its holder poses, so the two never come apart (a far NPC's sword updates with its hand).
  • Between those frames it's carried along when the game moves that actor. One stuck to something posing every frame (a player, a camera) is carried too.
  • Spawned actors, and actors whose stack only follows themselves, take Lod like the cast (a projectile far off poses less often, a rig off screen stops posing). That covers Motion Warps and any built-in constraint aimed at the actor's own role or parts, or at a spot in scene space: foot Locks, a Floor under itself.
  • A driver, a custom constraint, or a constraint aimed at another role keeps an actor posing every frame, even off screen.

Rigs in a ViewportFrame ​

An inventory card, a reveal or a shop preview plays like any cast: put the rig in the frame's WorldModel before Play.

  • Level of detail judges the card by how it shows, not by the world camera.
  • It rests while it or anything above it is hidden, its ScreenGui is disabled, it's scrolled out of a list that clips it, or it's off the screen. It picks up when shown again.
  • On screen it counts as a rig as far away as one that size would look. A crowd of icon-sized cards poses less often, while a big card keeps every frame.
  • MaxDistance leaves it alone.
  • Copies the scene spawns go into the card's WorldModel.
  • A client's Play on it never replicates.

Fast playback

Hundreds of characters or a thousand props can play at once:

  • Each channel is prepared once per scene, so nothing searches for keys every frame.
  • Joints are written without reading them back.
  • Events are found by time instead of scanning the scene.
  • The parts a frame moves go in one bulk move.

Signals ​

SignalFires

  • The others: Looped, MarkerReached(markerName, payload), LengthChanged(length), CameraAttached, CameraDetached, ShotChanged(role?).
  • Signals stay connected across plays.

Replaying and setters ​

  • A track can be replayed: Play after it ends plays it again.
  • Play while it plays restarts it. An Ended handler that plays it again wins.
  • Setters work before and during a play and last across plays. They never change the options table you passed.

Mid-play ​

  • SetCast lets go of the old instance (joints back to the Animator, movement lock undone) and binds the new one aligned from now.
  • SetOptions re-clamps Range, rebinds on Anchor/Align, and applies LockMovement, Manual, FadeIn/FadeOut and FreezeActors/CommitRoot live.
  • StartTime and Audience apply from the next Play.

Stopping and time ​

  • At the end of Stop(fadeOut), joints go back to what the Animator gives them. Roots and properties keep the last value written.
  • The weight and fades apply to joints and properties, never to the root.
  • Play time follows the shared server clock (workspace:GetServerTimeNow()), never the frame delta, so a hitch on one machine does not leave it behind.

Time maps ​

  • SetTimeMap(knots) (or the TimeMap option) pins play time to server time. Each knot is { realTime = serverTime, clipTime = seconds }, sorted by realTime, at least one. Bad knots error.
  • Between knots the play runs at whatever speed reaches the next clip time. Before the first knot it holds, after the last it keeps the last stretch's speed (speed 1 with one knot).
  • Markers and Event blocks fire once each as the mapped time crosses them, however big the frame. A stretch that runs back plays backwards and fires what it crosses again, like a negative speed.
  • Set mid-play, it plays forward to where the map is now (firing what it crosses) or jumps back. SetTime and StepTime do nothing while a map is set; SetSpeed waits until it's cleared.
  • It replicates with PlayForAll and server Play, late joiners too: every machine reads the knots at its own server time and shows the same frame. A one-knot map also starts a late client's own Play on the right frame.

Root motion ​

  • Relative to the scene origin, each actor's root part, or per actor (Hub > Scene origin > Characters move from).
  • Align applies at the start, and only to actors with a root track:
AlignWhat it does
SnapTeleports to the authored spot.
BlendSlides over FadeIn, 0.25 s by default.
NonePlays where it stands.
  • An older scene's Warp plays as Blend (a Motion Warp bends motion onto a target).

Audio lanes ​

  • The scene's clips play wherever the scene plays: Play on one client, PlayForAll for everyone.
  • Each clip plays at its volume times its lane's, flat from SoundService or from its 3D part.
  • Clips start partway on SetTime, a late start or a late join.
  • A clip's Sound template must be somewhere the playing side can see (ReplicatedStorage or Workspace for clients).
  • Roblox animations can't hold sound: Export lists "Audio: N clips" under what needs the runtime.

Attachments ​

Attach, Detach and Back to rig keys.

  • An attached root, joint or bone follows its target from its Attach key, keeping where it was then, with its own keys on top.
  • It stays put from a Detach key.
  • It rejoins its rig from a Back to rig key: snapped back into place, eased over its blend, or where it is.
  • Each Attach key carries the grip saved when it was made. An older key without one keeps the grip it has when the play reaches it.
  • In a game, a Detach key drops the object where it is at that moment, not at the spot saved in Studio, so it lands right when the target or the anchor is somewhere else.
  • A target the scene doesn't move (a dummy, an NPC, a player) is read where it stands now, so an object stuck to a walking target walks with it.
  • A Model actor that moves by a part (Moves by) is placed by its part of the same name in whatever model plays the role, so swapped designs line up.
  • Worked out from the time, so SetTime and StepTime land where a straight play would.
  • A target that is not in the cast holds it where it was.
  • A target whose root a generator moves (a Shake on its root, with or without root keys) carries what rides it the same way in a game as in Studio.

Held props ride a joint ​

  • While an Attach key holds a part or model actor on a part (a hand) or an Attachment in one, the runtime joins it to the holder with a Motor6D named AcesMotionHold inside the prop.
  • That happens when the prop is unanchored or its Unanchor switch is on.
  • A held prop costs nothing per frame. Keys on the prop itself still apply on top.
  • A model's parts that aren't joined to its main part (its Moves by part, else its PrimaryPart) are welded to it for the hold (AcesMotionHoldWeld).
  • The joint goes when the hold ends: a Detach key, another target, SetTime outside the hold, Stop. Anchored, Massless and CanCollide go back to how they were, so the prop stays where it was.
  • Each client makes its own joint (nothing replicates); the server never does.
  • These keep the per-frame math: an anchored prop with Unanchor off, a held rig, a rig's own joint, a Bone target, and a prop with constraints or drivers.

Constraints ​

Track To, Copy, Limit, Floor and the rest.

  • They run live after keys and attachments, each row's stack in order with its generators, so a constrained camera aims at whoever plays the target role.
  • A constraint whose target isn't in the cast does nothing.
  • A distance fade weighs each constraint by how far it is from what it measures to, every frame.

Drivers ​

Copy, Distance, Axis, Speed, Property and custom.

  • They run live in the same stacks as generators and constraints, on roots, joints, properties or one channel of them.
  • A source the scene animates is read from the scene at that moment, so SetTime and late joins land right.
  • A source the scene doesn't animate (a game-set attribute, a player, a physics object) is read live every frame. Its Speed and Smooth follow it between frames.
  • A driver whose source is missing does nothing (the keys play). One that reads what it drives is ignored.
  • A whole Color3 driven by a number picks its colour from the block's colour ramp.

Roles the game fills in ​

An actor's Filled by.

  • When the game's cast leaves the role out, the runtime fills it with one of these:
    • the local player's character
    • the nearest player's character (nearest to the scene origin)
    • the player's camera
    • the nearest (or first) object with a tag
  • It picks again 10 times a second as players respawn and move.
  • A role the game casts itself always wins.
  • The server has no local player or camera, so those roles stay empty there.

Camera actors ​

  • They take the camera (CFrame and FOV) on a client's full play unless Camera is false. SetCamera(false) gives it back mid-play.
  • A switch key's Blend glides into its shot from the camera before it, eased in and out, the outgoing camera still moving as keyed.
  • The first shot, or one after a gap, glides from the player's view.
  • With several camera actors, only the live one drives the camera. The scene's Camera track switch keys choose it:
    • the last switch at or before the time
    • before the first switch, its camera
    • with no switches, the first camera actor in the cast
    • a muted camera or track is skipped
  • Scrubbing, SetTime and playing all agree.

Spawned actors ​

  • Cloned from their template into workspace.AcesMotionSpawned at their spawn frame, anchored, at their socket or the origin.
  • The template is found by its AcesMotionTemplate tag and id wherever it is, else by its saved path like ReplicatedStorage/AcesMotionTemplates/SlashArc.
  • Destroyed at their Until, or Lifetime seconds after the scene ends, or when it ends.
  • With Linger on, a spawned actor that disappears mid-scene stays its Lifetime more so its trails and particles finish.
  • A Parent to actor goes inside that part, welded.
  • Scrubbing back before the spawn frame removes the clone.
  • A looped play keeps its clones between passes (out of the world, put back on the next pass) instead of cloning again.
  • Under PlayForAll the clones are client-side (visual only).

Markers and action blocks ​

  • Markers fire MarkerReached and GetMarkerSignal.
  • Event blocks (params Name, Payload) fire those and OnEvent.
  • Other action blocks run the module registered under their Action name, only in Full mode.
  • Blocks are added on the Timeline's action tracks; their parameters are edited in the Inspector from the next update.

Motion Warps ​

  • They re-fit each trip to where things really are. A target the scene doesn't move is read where it stands now.
  • Aim at launch keeps where it was when the trip began, each play and each loop.
  • After the trip a warp keeps its landing until the next warp on the row, or until an Attach or Detach key on that row takes the actor over (a sticky shot that drops later).
  • One timed By speed is worked out when the play reaches it (from where its start and target are then). The play's Length follows, and LengthChanged fires.
  • Marker holds freeze the scene (or one actor). A Camera kick shakes the local camera over a scene marker's hold.

Repeated actors ​

  • A Per target actor plays one copy per item of its Over role's list (Cast = { Targets = { a, b, c } }). An empty list plays none.
  • The other items play as "Targets#2", "Targets#3"... in the cast, which networked copies use, and each copy lands on its own item.
  • A Count actor plays its copies with their Spread.
  • Each copy has its own warp, timing and Stagger, and its actor markers carry Target.
  • The play lasts until the last copy ends.

Layers ​

  • Layers play in games as in Studio: each actor's keys on a layer blend over Base by the layer's mode, weight curve, mask, mute and solo.
  • options.Layers = { Polish = 0.5 } and Track:SetLayerWeight(name, weight) scale a layer's authored weight by its name from the next frame (under PlayForAll too).
  • Not at runtime yet: modifiers.

Networking ​

One RemoteEvent, AcesMotionRemote, under the runtime module, from server to clients.

  • The only thing a client sends is its own play on a model it owns, which the server checks and relays.
  • Messages carry the server clock, so a client re-anchors rather than drifts. It jumps without firing events when more than 0.05 s off.
  • Each play sends its scene as the folder, the scene's permanent id and its name. The receiving side uses the first it can resolve, so renamed scenes, scenes found through a reference and late joiners all get the same scene.
  • Late joiners receive the live tracks and start at the current time (a looped one wrapped).
  • Streamed-in actors (StreamingEnabled): cast members are tagged AcesMotionCast with an AcesMotion_CastId attribute, and a client binds a member that was not streamed in when it appears.
  • The server sends the anchor it resolved and each moved actor's start root, so every client aligns alike.
  • A server Play shares itself as a joints-only copy (plus the owning client's own character root).

Frozen actors under PlayForAll ​

  • FreezeActors anchors moved actors on the server while a PlayForAll plays.
  • CommitRoot then pivots them to where the clients left them, and unanchors them. Attach keys, Motion Warps, root generators and constraints are included: the server solves those roots each frame meanwhile, so launches and drop spots match.
  • An actor counts as moved when the scene keys, attaches or stacks its root. Player characters are never frozen.
  • Track.Started / Ended let games pause and resume NPC logic.

Client-only games

The server never needs to require the runtime for a client-only game.
