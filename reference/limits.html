Limitations ​

Some of AcesMotion's behaviour comes from Roblox itself. The table below pairs each engine limit with what AcesMotion does about it; the current limits of AcesMotion follow.

Engine limitations, and how AcesMotion works around them ​

Roblox does thisSo AcesMotion does this
A joint's Transform never replicates between server and clients.Every client evaluates joints itself. The server sends one message per play with the server clock instead of a stream of poses.
A Roblox animation holds one rig's joints and nothing else.Cameras, parts, properties, sounds and effects play through the runtime from scene data. Joint-only scenes still export natively.
Studio's Animator samples a CurveAnimation 30 times a second.Export defaults to KeyframeSequence, which plays every key exactly.
In edit mode a joint's Transform moves nothing until the Animator steps.The preview steps the Animator after every pass so poses show while you scrub.
IKControl doesn't solve in edit mode.AcesMotion has its own IK solver, used for pins, context IK and every preview.
Studio's Move and Rotate tools rewrite a dragged part's Motor6D.AcesMotion poses with its own gizmo and holds the viewport mouse while a scene is open.
Studio keeps Delete, Ctrl+C / V / X / D and a few others even while a plugin window has focus, and a plugin can't read global shortcut bindings.Defaults avoid those keys (copy is Shift+C, paste Shift+V), and the Timeline sets Studio's selection aside while the pointer is over it, so a stray Delete can't remove your rig.
A plugin can't see keys held in its own window through UserInputService:IsKeyDown.Modifiers come from each input event instead.
Studio's PluginMenu can't grey out or tick items.AcesMotion draws its own menus, so every item can explain why it's disabled.
Studio's Undo discards every unrecorded change since the last step.The preview rests the stand-ins around every undo step and poses them again after.
A Sound's Play() does nothing in edit mode.The preview plays hidden AudioPlayer copies with the Sound's effects.
Studio can't fast-forward a particle emitter.The preview shows frozen particle copies for the frame you're on.
Roblox's Animation Graph can't be authored by plugins.Out of scope. Scenes and layers handle blending instead.

Current limits ​

Keys and focus ​

Studio decides which keys reach a plugin, so a few can't be used or may clash.

Keys Studio keeps ​

  • Studio keeps Delete, Ctrl+C, Ctrl+V, Ctrl+X, Ctrl+D, Shift+X, O, , and . for itself even while a plugin window has focus.
  • Any key bound in File > Customize Shortcuts is global.
  • A plugin cannot read those bindings, so any default can clash on someone's machine. Rebind in Settings (four keys) or in Studio's shortcut editor.
  • If a Timeline key does nothing, the status bar says "Click the Timeline first, then press the key again ({name})."
  • Studio's own Ctrl+C, Ctrl+V, Ctrl+X, Ctrl+D, Ctrl+Z and Ctrl+Y can't be given to an AcesMotion command (Studio takes them first).
  • Studio has no API for a plugin to open its File > Customize Shortcuts editor.

Focus ​

  • The Timeline takes keyboard focus when the pointer enters it. After leaving it, Studio's W / E / R need a click in the viewport first.
  • On some setups a key may not reach the plugin:
    • the Timeline taking focus on hover (its hover keys still work over it whichever window has focus)
    • Tab (temporary pivot) in the viewport, since Studio's own draggers use it
    • J over the viewport
    • Ctrl+Shift+O
  • Studio installs can also bind keys like I, K and V to other actions, which is why the hold keys can be rebound.

Don't use Move or Rotate on a posed stand-in

Studio's own tools (Move, Rotate) rewrite the rig's joint offsets. Posing holds the mouse so that cannot happen by accident.

Settings gaps ​

  • Settings has no Navigation page yet (scroll and zoom presets). There is no UI for the zoom and pan bindings.
  • Settings > Shortcuts lists keys only, not mouse gestures (scroll, drags). Those are on the Mouse gestures page.
  • Crash recovery keeps one copy per scene (up to 20), written 2 s after each edit.
  • The recovery interval isn't a setting. How long copies are kept is (Settings > Storage).

Roblox animation export ​

  • A Roblox animation holds one rig and joints only.
  • Cameras, parts, property tracks, limb sizes, calls, attributes, root motion kept, modifiers and audio need the runtime. The export panel lists them.
  • Layers bake into the clip with Bake layers on, else the clip is Base alone.
  • Markers export natively (the payload as JSON text, 64 characters).

Curves are sampled

Studio samples a CurveAnimation on a fixed 30 per second grid, so a Constant step or a 10 ms spike softens. KeyframeSequence (the default) plays every exported keyframe exactly.

Keying and posing ​

  • BrickColor, Font and PhysicalProperties values cannot be keyed.
  • Content properties are keyed through their ContentId twin.
  • CFrame properties are posed in the viewport (the Inspector shows a read-only position). CFrame attributes are editable.
  • Mirror: a joint whose rest frame does not mirror its partner's exactly is left out of Paste mirrored. The status line counts them.
  • IK limits cover elbows and knees only.
  • Resize works on parts and models, not rigs.
  • Limbs only ghosts cannot split a skinned mesh.

Team Create ​

  • Only teammates who run AcesMotion show up. Someone without it is still in Studio's own collaborator list.
  • A teammate who stops sending (Studio froze, the connection dropped) disappears after 15 seconds.
  • Ping sends your playhead time, but nothing shows it on the teammate's side yet.
  • Rings show up to 256 picked keys per teammate. Past that, their selection shows as one band per row.
  • If three people change the same actor within the same second, an edit can be dropped after three tries. Its toast says so; run it again.
  • A teammate previewing a property track and you editing that exact property in Studio's Properties window at the same moment: your change isn't keyed.

Previews ​

What Studio's edit mode can't show exactly.

Effect preview ​

  • Particles show as frozen copies on the frame you are on (Studio cannot fast-forward an emitter). The arrangement may re-roll when you pause.
  • While playing, real emitters run at 1x and slower. Above 1x or in reverse the frozen copies take over.
  • Flipbooks step through their frames by a render-by-render timing trick, so a frame can be one off now and then.
  • Particles only age on rendered frames, so check timing with the viewport showing.
  • A scrolling Beam holds still while scrubbing (Roblox restarts a Beam's scroll whenever its speed is set).
  • The preview cap (100 to 10,000, default 1000) keeps every k-th particle. Real playback and games always show all.

Trails while scrubbing ​

  • Roblox draws a Trail only from where its attachments really moved.
  • So while you scrub, pause, play backward or faster than 1x, every Trail in the scene is drawn as a stand-in ribbon. It's built from where its two attachments were over its Lifetime: its colour, transparency and width over its life, its texture running the whole ribbon.
  • Playing forward at 1x or slower shows the real Trail again, started fresh.
  • A spawned actor's Trail stands in where its copy is now.

Sounds ​

  • A Sound's own Play() does nothing in edit mode, so AcesMotion plays hidden AudioPlayer copies with the Sound's effects and SoundGroups.
  • The copies are 3D by default, flat with "Play sounds in 2D while animating".
  • While scrubbing only short snippets play, not continuous audio.
  • Waveforms are read in 2 second chunks as they scroll into view.
  • A sound's length arrives in about half a second. Until then its bar is a short placeholder.
  • The Loading spinner on sound bars does not spin.

Markers ​

  • Marker payloads cannot be edited in the UI yet (they come from imports).
