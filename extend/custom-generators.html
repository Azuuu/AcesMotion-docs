Custom generators ​

A generator drives a value over a block of time, on top of its keys. AcesMotion ships with Shake, Wiggle, Oscillate and the rest of the built-in generators. When none of them makes the motion you want, you can write your own as a ModuleScript. It shows up in the Add generator menu next to the built-ins, gets an Inspector panel like theirs, and plays the same way in Studio and in games.

Write one when you want a motion you'd otherwise key by hand over and over: a hover bob, a heartbeat pulse, a pendulum swing, a drift with your own easing. If you only need different settings on a built-in generator, save a preset instead.

Make one in Studio ​

  1. In the Timeline, right click the lane of a property, joint or root row and choose Add generator > New custom generator...
  2. AcesMotion creates a ModuleScript named NewGenerator, puts its first block on that row, and opens the script. The module goes inside what you have selected in the Explorer, or into ReplicatedStorage when nothing is selected.
  3. Edit the script. AcesMotion reloads it when you change it, and the block follows.

The new module already works: it's a smooth swirl you can edit into your own motion. Rename the module to name the generator.

To turn a ModuleScript you already have into a generator, select it in the Explorer and choose Add generator > Use selected module as a generator. That adds the AcesMotionGenerator tag. Any ModuleScript with this tag is a generator, wherever it sits in the place.

Each custom generator also gets an AcesMotion_GeneratorId attribute. Its blocks remember the generator by this id, so renaming the module keeps them working. Leave the attribute alone. A module made by an older version has AcesMotion_ActionId instead, which still works: AcesMotion copies it to AcesMotion_GeneratorId the next time it touches the module.

The module ​

A generator module returns a table. Only Offset is required.

luau
--!strict
export type Settings = {
	Height: number,
	Speed: number,
}

local Generator = {
	Description = "What it does, in a sentence.",
	Kinds = { "Number", "CFrame" },
	Blend = "Add",
	DefaultAxes = { 2 },
	Params = {
		{ Name = "Height", Type = "Number", Default = 0.5, Min = 0, Unit = "studs", Description = "How far it moves." },
		{ Name = "Speed", Type = "Number", Default = 1, Min = 0, Unit = "Hz", Description = "Repeats a second." },
	},
	LoopParam = "Speed",
}

function Generator.Offset(seconds: number, duration: number, channel: number, settings: Settings, noise: (x: number) -> number): number
	return math.sin(seconds * settings.Speed * 2 * math.pi) * settings.Height
end

return Generator
FieldTypeWhat it does
OffsetfunctionRequired. Returns how far to move one channel of the value at one moment. See below.
Descriptionstring?The tooltip on its blocks and on its item in the Add generator menu.
Kinds{ string }?The kinds of value it can drive. Leave it out for "Number", "Vector3", "Color3" and "CFrame".
Blendstring?How a new block combines with the keys: "Add" (the default), "Multiply" or "Replace". Each block can change it.
DefaultAxes{ number }?Which channels of a CFrame a new block drives: 1 to 3 are position, 4 to 6 rotation. Leave it out for all six.
Params{ Param }?The block's settings, shown in the Inspector in this order.
LoopParamstring?The setting that controls how often it repeats. With it, the block's Snap to Loop can round it so whole repeats fit the block. Leave it out for a motion that plays once.

Kinds and channels ​

Offset is called once per channel of the value, every frame. The channel number tells you which part of the value you're moving:

KindChannels
"Number"1
"Vector3"1 X, 2 Y, 3 Z
"Color3"1 R, 2 G, 3 B
"CFrame"1 to 3 position in studs, 4 to 6 rotation in degrees
"Vector2"1 X, 2 Y
"UDim"1 Scale, 2 Offset
"UDim2"1 X Scale, 2 X Offset, 3 Y Scale, 4 Y Offset
"Bool"1: the value is on while 1 plus the offset is at least 0.5, so return 0 for on and -1 for off

A number's one channel is channel 1, the same index as a CFrame's X position. When the two need different handling, read the sixth argument, kind.

Offset ​

luau
function Generator.Offset(seconds, duration, channel, settings, noise, kind): number
ArgumentWhat it is
secondsTime into the block, in seconds.
durationThe block's length, in seconds.
channelWhich channel of the value (see the table above).
settingsThe block's settings at this moment, one field per param. A keyed setting gives its keyed value here.
noisenoise(x) returns smooth noise of about -1 to 1, seeded per block and per channel. Use it for anything random.
kindThe kind of value being driven, such as "Number" or "CFrame". Optional to read.

Return a number. AcesMotion applies the block's blend, Influence and fades to it for you. An Offset that errors or returns something other than a number adds nothing, and Output shows a warning once.

Params ​

Each entry in Params becomes a field in the generator's Inspector panel, and its value arrives in settings under its Name.

TypeValue in settingsExtra fields
"Number"numberMin, Max, Unit
"Integer"numberMin, Max, Unit
"Boolean"boolean
"Enum"the picked option, a stringOptions = { "A", "B" }

Every param takes Name, Type, and an optional Default and Description (the field's tooltip). Without a Default, a number starts at 0, a Boolean at false and an Enum at its first option. Every number setting can be keyed on the block, like a built-in generator's.

Give a time setting Unit = "s" (or "f" for frames): the Inspector shows it in seconds or frames, following the Timeline's ruler, and your code always gets the unit you declared. Module params has the full rules for every field and type, and the setting names generator blocks already use.

Example: Hover Bob ​

A gentle up and down bob with an optional random drift. On a CFrame (a prop's root, a camera) it moves only the Y position by default. On a number it bobs the value itself, such as a light's Brightness.

luau
--!strict
export type Settings = {
	Height: number,
	Speed: number,
	Drift: number,
}

local TAU = 2 * math.pi

local Generator = {
	Description = "Bobs up and down, with a little random drift if you want it.",
	Kinds = { "Number", "CFrame" },
	Blend = "Add",
	DefaultAxes = { 2 },
	Params = {
		{ Name = "Height", Type = "Number", Default = 0.5, Min = 0, Unit = "studs", Description = "How far it bobs each way." },
		{ Name = "Speed", Type = "Number", Default = 0.5, Min = 0, Unit = "Hz", Description = "Bobs a second." },
		{ Name = "Drift", Type = "Number", Default = 0, Min = 0, Max = 1, Description = "How much random wander joins the bob." },
	},
	LoopParam = "Speed",
}

function Generator.Offset(seconds: number, duration: number, channel: number, settings: Settings, noise: (x: number) -> number): number
	local bob = math.sin(seconds * settings.Speed * TAU)
	local wander = noise(seconds * settings.Speed)
	return (bob + wander * settings.Drift) * settings.Height
end

return Generator

Name the module HoverBob and it appears as HoverBob at the bottom of the Add generator menu. The noise is read at seconds * settings.Speed, the same rate as the bob, so Snap to Loop loops the drift along with the wave.

In the Timeline and the Inspector ​

Custom generators are listed after the built-ins in every Add generator menu: a row's lane, its header and the Inspector's property rows. A generator that can't drive a row's kind of value is greyed with the reason. A module that fails to load shows as "HoverBob (could not load)", and Output says why.

Its blocks look and behave like a built-in's: move, trim and fade them, key their settings, pick a blend, and Bake to keys when you want plain keys. The Inspector panel lists your params under Settings, in the order you wrote them, along with the usual Timing, Blend and preview.

Settings > Actions > Run custom generators in Studio switches all custom generators off in Studio. Turn it off if one misbehaves: its blocks keep their settings and add nothing. Games still run them.

In games ​

The runtime registers every ModuleScript tagged AcesMotionGenerator when it loads, and any that are tagged or stream in later. Keep the module where both the server and clients can require it, such as ReplicatedStorage. A module in ServerStorage or ServerScriptService can't be required by clients, so their plays skip its blocks.

If you keep a generator module somewhere without the tag, register it yourself before playing:

luau
local ReplicatedStorage = game:GetService("ReplicatedStorage")
local AcesMotion = require(ReplicatedStorage.AcesMotion)

AcesMotion.RegisterGenerator("HoverBob", require(script.HoverBob))

The name must match the generator's name in the scene, which is its module name. RegisterGenerator raises an error when the table has no Offset function. Call it on the server and on every client, as the tag would.

Tips and pitfalls ​

  • Keep Offset pure: the same arguments always return the same number. Don't keep state between calls or read the clock. Scrubbing, Bake to keys, and plays that start partway through all depend on it.
  • Use noise for randomness, never math.random or Random.new(). The noise is seeded per block, so every player sees the same motion, and Reseed in the block's menu picks a new one.
  • Offset runs for every channel of every block every frame, in Studio and in games. Keep it to a little math.
  • Rotation channels are in degrees, not radians.
  • Two generators can't share a name, and a module named like a built-in (Shake, Spin) is skipped with a warning in Output.
  • Fades and Influence are applied for you. Don't fade in Offset unless the fade is part of the motion itself.
