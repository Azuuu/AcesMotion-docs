Custom actions ​

A custom action is your own Luau code, placed on the Timeline as a block. It runs when the playhead enters the block and cleans up when the playhead leaves, in Studio's preview and in games. Use one for anything a key can't hold: spawning a part, turning on a trail, showing a hitbox, starting a particle burst, calling into your own effects code. Each block has its own settings in the Inspector, so one action can serve a whole game.

This page walks through writing one. The custom actions API reference lists every field, param type and context value in full.

If all you need is a signal to your game code at a moment ("Hit", "Footstep"), use the built-in Event block and AcesMotion.OnEvent instead. Events fire on the server too; custom actions are better for effects.

Make one in Studio ​

  1. Give an actor an action track: right click the actor's row > Add action track.
  2. Right click an empty spot of the track's lane and choose Add block > New custom action...
  3. AcesMotion creates a ModuleScript named NewAction, puts its first block at the frame you clicked, and opens the script. The module goes inside what you have selected in the Explorer, or into ReplicatedStorage when nothing is selected.
  4. Edit the script. AcesMotion reloads it when you change it, and the next run of the block uses the new code.

The template is fully commented, with a worked example (a light on a part) commented out inside Run. Rename the module to rename the action; the Name field sets the title on its blocks.

To turn a ModuleScript you already have into an action, select it in the Explorer and choose Add block > Use selected module as an action. That adds the AcesMotionAction tag. Any ModuleScript with this tag is an action, wherever it sits in the place.

Each custom action also gets an AcesMotion_ActionId attribute that its blocks remember it by. Leave the attribute alone.

The module ​

An action module returns a table with a Run function, plus a few optional fields:

FieldWhat it does
NameThe title on its blocks and in the Add block menu. Without it, the module's name.
DescriptionThe tooltip on its blocks.
IconAn image id drawn on its blocks.
HasDurationtrue for a bar with a length. Leave it out or set false for an instant chip that fires once.
ParamsThe block's settings, shown as fields in the Inspector in this order.
Run(context, params)Called when the playhead enters the block. Return a cleanup function, or nothing.
Scrub(context, params, seconds)Optional. Called on every step while the playhead is inside the block.
Recast(context, params, changedRoles)Optional. A role this block uses got a new instance while it runs.

A quick instant action can also be just a function, which becomes its Run:

luau
return function(context, params)
	print("Hit at frame", context.Frame)
end

Run and cleanup ​

Run gets the block's context and its params. Whatever it makes, add to context.Trove, which cleans everything up when the block ends or the scene stops. For anything the Trove can't undo (a property you changed on an existing part), return a cleanup function. It runs when the playhead leaves the block or the scene stops.

Scrub ​

Scrub runs every step while the playhead is inside a block with a duration, in games as well as in Studio, with seconds set to the time into the block. Put anything that should follow the playhead exactly here, such as a size that grows over the block. When you drag the playhead back and forth in Studio, the effect follows.

Params ​

Each entry in Params becomes a field in the block's Inspector panel. Its value arrives in params under its Name, or its Default when the block hasn't set one. The common types:

TypeValue in params
"Number", "Integer"number (takes Min, Max, and for numbers Unit)
"Boolean"boolean
"String"string
"Color3", "Vector3"that value
"ActorPart"a path such as "Hero/RightHand": pass it to context.GetPart
"Actor"a role name: pass it to context.GetActor

Module params covers every type, including Enum, Joint, Asset, Template, Marker and Table, with its Inspector field and what a block gets without a Default.

The context ​

The fields you'll use most:

FieldWhat it is
GetPart(path)A part, attachment or bone inside an actor, from an ActorPart value.
GetActor(role)An actor's model or part by its role.
TroveAnything added to it is cleaned up when the block ends or the scene stops.
SecondsSeconds into the block.
IsPreviewtrue in Studio's preview, false in games.
IsServertrue when running on the server.
AnchorWhere the scene's origin is in the world.

See the context for the full list, including the scene time, frame and play speed.

Example: Ground Ring ​

A glowing ring that spreads out along the ground from a part while the block plays: a landing, a stomp, a power-up. Run makes the ring and Scrub grows it, so it grows at the same rate however you scrub.

luau
local Action = {
	Name = "Ground Ring",
	Description = "A glowing ring that spreads out from a part while the block plays.",
	HasDuration = true,
	Params = {
		{ Name = "Part", Type = "ActorPart", Description = "The part the ring spreads from." },
		{ Name = "Speed", Type = "Number", Default = 12, Min = 0, Unit = "studs/s", Description = "How fast the ring grows." },
		{ Name = "Color", Type = "Color3", Default = Color3.fromRGB(120, 200, 255), Description = "The ring's colour." },
	},
}

-- Each running block's ring, by its context.
local rings = setmetatable({}, { __mode = "k" })

function Action.Run(context, params)
	local part = if params.Part then context.GetPart(params.Part) else nil
	if not (part and part:IsA("BasePart")) then
		return nil
	end
	local ring = Instance.new("Part")
	ring.Shape = Enum.PartType.Cylinder
	ring.Material = Enum.Material.Neon
	ring.Color = params.Color
	ring.Anchored = true
	ring.CanCollide = false
	ring.CanQuery = false
	ring.CastShadow = false
	ring.Size = Vector3.new(0.2, 1, 1)
	-- A cylinder's length runs along X: turn it flat, at the bottom of the part.
	ring.CFrame = CFrame.new(part.Position - Vector3.new(0, part.Size.Y / 2, 0)) * CFrame.Angles(0, 0, math.rad(90))
	ring.Parent = workspace
	context.Trove:Add(ring) -- removed when the block ends or the scene stops
	rings[context] = ring
	return function()
		rings[context] = nil
	end
end

function Action.Scrub(context, params, seconds)
	local ring = rings[context]
	if ring then
		local width = 1 + seconds * params.Speed
		ring.Size = Vector3.new(0.2, width, width)
		ring.Transparency = math.clamp(seconds, 0, 1)
	end
end

return Action

Name the module GroundRing, tag it (or make it with New custom action... and paste this in), then add a Ground Ring block and pick a foot in its Part field. Stretch the block to set how long the ring spreads.

In the Timeline and the Inspector ​

Custom actions are listed by their Name in every action track's Add block menu, after Event. A module that fails to load is greyed with "(could not load)" after its name, and Output says why. A block with a duration starts half a second long; an instant is a chip on its frame. Select a block and the Inspector shows Timing and one row per param; right click a row for Reset to default. With several blocks of one action selected, an edit applies to all of them.

In Studio, blocks with a duration run and clean up as the playhead moves in and out of them, playing or scrubbing. Instant blocks fire only while playing, unless Settings > Actions > Fire instant actions while scrubbing is on. Settings > Actions > Run custom actions in Studio switches all custom actions off in Studio; games still run them.

In games ​

The runtime registers every ModuleScript tagged AcesMotionAction under its module name when it loads, and any that are tagged or stream in later. Keep the module where both the server and clients can require it, such as ReplicatedStorage.

Actions run where the scene really plays: on the client for a client's own Play, on every client for PlayForAll, and on the server for a server Play. Under PlayForAll each client runs the action for itself, so a part it makes is local to that client. Do gameplay such as damage on the server, from an Event block or a marker, rather than inside an action that runs on every client. When it runs covers late joins, SetTime and StepTime.

To register a module kept without the tag, or a plain function, use AcesMotion.RegisterAction.

Tips and pitfalls ​

  • Add everything you create to context.Trove. In Studio the preview runs your code in edit mode, so a part you make and forget stays in the place.
  • Check context.IsPreview before anything that should only happen in a real game, such as dealing damage or sending a remote.
  • Check what GetPart and GetActor return. A param can be empty, and a game can play the scene with a different cast.
  • Errors in Run, Scrub and Recast are caught and shown in Output (a Scrub error once per block), so a broken action doesn't stop the scene. Watch Output while you work on one.
  • A Sound's own Play() does nothing in Studio's edit mode. To hear a sound in the preview, key the Sound's Play() call on the Timeline or put it on an audio lane instead of playing it from an action.
  • Without Recast, a block whose actor changes mid-play restarts: its cleanup runs, then Run again. Add Recast when the block should carry on and move what it made to the new actor.
