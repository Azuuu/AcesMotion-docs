Custom constraints ​

A constraint moves an actor's root or a joint from something else in the scene: it aims a head at a target, keeps a foot on the floor, copies another part's rotation. The built-in constraints cover the common cases. A custom constraint is your own ModuleScript that does the same job with your own rule. It sits on a row's Stack lane next to the built-ins, gets the same Inspector panel, Influence, fades and Distance fade, and plays the same way in Studio and in games.

Write one when you place or aim something by a rule the built-ins don't have: look at the midpoint of two characters, orbit a target, keep a prop between two hands, hover over a target. If you want an ongoing wobble or wave on top of keys, a custom generator is the better fit.

Make one in Studio ​

  1. In the Timeline, right click an actor's root row or a joint row (its header or an empty spot of its lane) and choose Add constraint > New custom constraint...
  2. AcesMotion creates a ModuleScript named NewConstraint, puts its first block on that row, and opens the script. The module goes inside what you have selected in the Explorer, or into ReplicatedStorage when nothing is selected.
  3. Edit the script. AcesMotion reloads it when you change it, and the block follows.

The template works as it is: it hovers its subject over a target, bobbing. Rename the module to name the constraint.

To turn a ModuleScript you already have into a constraint, select it in the Explorer and choose Add constraint > Use selected module as a constraint. That adds the AcesMotionConstraint tag. Any ModuleScript with this tag is a constraint, wherever it sits in the place.

Each custom constraint also gets an AcesMotion_ConstraintId attribute. Its blocks remember the constraint by this id, so renaming the module keeps them working. Leave the attribute alone. A module made by an older version has AcesMotion_ActionId instead, which still works: AcesMotion copies it to AcesMotion_ConstraintId the next time it touches the module.

The module ​

A constraint module returns a table. Only Solve is required.

FieldTypeWhat it does
SolvefunctionRequired. Returns where the subject should be, at full strength. See below.
Descriptionstring?The tooltip on its blocks.
Drives{ Position: boolean?, Rotation: boolean? }?What it takes over at full strength. Those parts of the posing gizmo grey out while you pose its subject.
Params{ Param }?The block's settings and targets, shown in the Inspector in this order.

Solve ​

luau
function Constraint.Solve(world: CFrame, context: Context): CFrame

world is where the subject is now in world space: the root's CFrame, or the joint's part, after its keys and the blocks above this one on its row. Return the CFrame it should have when the block is at full strength. AcesMotion blends between world and your result by the block's Influence, fades and Distance fade, then passes the result on to the blocks below.

If Solve errors or returns something other than a CFrame, the subject stays where it was, with one warning in Output. If a target the constraint needs is unset or missing, Solve isn't called at all.

context holds:

FieldTypeWhat it is
Targets{ [string]: CFrame? }Each Target param's world CFrame now, by its name. nil when it's unset or missing (only possible for an optional target).
Settings{ [string]: any }The block's settings now, one field per param. Targets aren't in here. A keyed setting gives its keyed value.
TimenumberSeconds into the block.
DurationnumberThe block's length in seconds.
ParentCFrameWhat the subject hangs from: a joint's parent part, or for a root, the scene origin.
OriginCFrameThe scene origin.
FpsnumberThe scene's frame rate.
RestCFrame?The subject now from its keys alone, before any block on its row.
Sample(name: string, seconds: number) -> CFrame?A target at another time in the block, by the target's name.
Self(seconds: number) -> CFrame?The subject from its keys alone at another time in the block.

Sample and Self let a constraint look ahead or behind, the way the built-in Delay and Face Motion do, without keeping memory between frames.

Params ​

Each entry in Params becomes a row in the constraint's Inspector panel.

TypeValueExtra fields
"Target"the target's CFrame, in context.TargetsOptional = true when it works without one
"Number"numberMin, Max, Unit, Keyable
"Integer"numberMin, Max, Unit, Keyable
"Boolean"boolean
"Enum"the picked option, a stringOptions = { "A", "B" }
"Axis"one of "+X", "-X", "+Y", "-Y", "+Z", "-Z"

Every param takes Name, Type, and an optional Default, Description (its tooltip) and Label (the text shown in the Inspector when it isn't the name, such as "Keep rotation" for KeepRotation). Without a Default, a number starts at 0, a Boolean at false, an Enum at its first option and an Axis at "-Z", Roblox's front.

A Target param gets a target picker like the built-ins have: the part list, a viewport pick button and Use selection. Number settings can be keyed on the block; add Keyable = false to one that shouldn't be. Give a time setting Unit = "s" (or "f" for frames): the Inspector shows it in the Timeline ruler's units, and your code always gets the unit you declared. Module params has the full rules for every field and type, including how params named for limits and axes are grouped in the Inspector.

Example: Look Between ​

Aims its subject at a point between two targets: a head watching two characters talk, a camera framing both fighters. Bias slides the point from the first target to the second, and since it's a number setting, you can key it to shift attention across the shot.

luau
--!strict
export type Settings = {
	Bias: number,
}

type Context = {
	Targets: { [string]: CFrame? },
	Settings: Settings,
}

local Constraint = {
	Description = "Aims at a point between two targets.",
	Drives = { Rotation = true },
	Params = {
		{ Name = "First", Type = "Target", Description = "One end of the line it looks along." },
		{ Name = "Second", Type = "Target", Description = "The other end." },
		{ Name = "Bias", Type = "Number", Default = 0.5, Min = 0, Max = 1, Description = "0 looks at First, 1 at Second." },
	},
}

function Constraint.Solve(world: CFrame, context: Context): CFrame
	local first = context.Targets.First :: CFrame
	local second = context.Targets.Second :: CFrame
	local point = first.Position:Lerp(second.Position, context.Settings.Bias)
	if (point - world.Position).Magnitude < 0.001 then
		return world
	end
	return CFrame.lookAt(world.Position, point)
end

return Constraint

Both targets are required, so a block with one of them unset does nothing and Solve can treat them as set. CFrame.lookAt points the subject's front (-Z) at the point and keeps its position, which suits heads and cameras. For a part whose front is another axis, add an "Axis" param and turn the result to match.

In the Timeline and the Inspector ​

Custom constraints are listed under Custom at the end of the Add constraint menu. A module that fails to load shows as "LookBetween (could not load)", and Output says why. Its blocks draw in mint like the built-ins, with the usual move, trim, fade, Bake to keys and presets. Select one and the Inspector shows Timing, your targets and settings, Blend with Influence, fades and Distance fade, and Preset.

Settings > Actions > Run custom constraints in Studio switches all custom constraints off in Studio. Turn it off if one misbehaves: its blocks keep their settings and do nothing. Games still run them.

In games ​

The runtime registers every ModuleScript tagged AcesMotionConstraint when it loads, and any that are tagged or stream in later. Keep the module where both the server and clients can require it, such as ReplicatedStorage. A game that can't find a constraint leaves its blocks out, and the keys play on their own.

To use a module kept without the tag, register it yourself on the server and every client before playing:

luau
local ReplicatedStorage = game:GetService("ReplicatedStorage")
local AcesMotion = require(ReplicatedStorage.AcesMotion)

AcesMotion.RegisterConstraint("LookBetween", require(script.LookBetween))

The name must match the constraint's name in the scene, which is its module name. RegisterConstraint raises an error when the table has no Solve function.

Tips and pitfalls ​

  • Keep Solve pure: the same inputs give the same answer, with no memory between calls. Scrubbing, SetTime, Bake to keys, and plays that start partway through all depend on it. Use Sample and Self when you need another moment.
  • Return a world CFrame. A joint's own value is local to its parent, but Solve always works in world space, and AcesMotion converts back for you.
  • Return world unchanged when the math has no good answer (a target on top of the subject, an aim straight along the up axis). A CFrame with NaN in it is thrown away, so the subject stays put, but a near-zero direction can still snap.
  • Solve runs every frame for every block, in Studio and in games. Keep it to a little math.
  • Two constraints can't share a name, and a module named like a built-in (Floor, Delay) is skipped with a warning in Output.
